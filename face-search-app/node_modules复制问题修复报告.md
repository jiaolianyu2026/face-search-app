# node_modules 复制问题修复报告

## 问题描述

打包的应用启动时报错：
```
Error: Cannot find module 'D:\...\frontend\node_modules\vite\bin\vite.js'
```

## 根本原因

打包脚本使用 `xcopy` 命令复制 `node_modules` 目录时，由于以下原因导致复制不完整：

1. **Windows 路径长度限制**：Windows 默认路径长度限制为 260 字符，node_modules 中的深层嵌套目录经常超过此限制
2. **符号链接处理**：node_modules 中包含符号链接，xcopy 可能无法正确处理
3. **文件数量巨大**：node_modules 包含数万个文件，xcopy 在处理大量文件时可能出现问题
4. **权限问题**：某些文件可能有特殊权限，导致复制失败

### 实际情况

- 源目录：69 个模块目录
- 复制后：仅 5 个目录（.bin, .vite, @babel, @esbuild, @rollup）
- 缺失关键模块：vite, react, react-dom, axios 等

## 解决方案

### 1. 修改打包脚本（长期方案）

将 `xcopy` 替换为 `robocopy`，后者更可靠：

```batch
robocopy frontend\node_modules %DEPLOY_DIR%\frontend\node_modules /E /NFL /NDL /NJH /NJS /nc /ns /np
```

**robocopy 优势**：
- 更好地处理长路径
- 更可靠的符号链接支持
- 更好的错误处理
- 断点续传能力

### 2. 提供安装脚本（用户端方案）

创建 `install_frontend_deps.bat` 脚本，让用户在部署后自行安装依赖：

```batch
cd frontend
npm install
```

**优势**：
- 100% 可靠
- 依赖版本始终最新
- 避免打包体积过大
- 适应不同环境

### 3. 改进检查脚本

增强 `check.bat` 脚本，检测 vite 模块是否存在：

```batch
if exist "%APP_ROOT%\frontend\node_modules\vite" (
    echo [OK] vite 模块存在
) else (
    echo [错误] vite 模块不存在
    echo 运行 scripts\install_frontend_deps.bat 安装
)
```

## 建议的部署策略

### 策略 1：完整打包（当前方案）

**优点**：
- 用户无需安装 Node.js
- 开箱即用

**缺点**：
- 打包体积大（500MB-1GB）
- 可能遇到复制问题
- 依赖版本固定

**适用场景**：
- 内网部署
- 用户无法访问 npm
- 需要离线安装

### 策略 2：轻量打包（推荐）

**方案**：
- 不打包 node_modules
- 提供 package.json 和 package-lock.json
- 用户运行 install_frontend_deps.bat

**优点**：
- 打包体积小（50MB）
- 100% 可靠
- 依赖始终最新

**缺点**：
- 用户需要安装 Node.js
- 首次启动需要安装依赖（3-5 分钟）

**适用场景**：
- 开发环境
- 用户有网络访问
- 需要灵活性

### 策略 3：混合方案

**方案**：
- 尝试打包 node_modules（使用 robocopy）
- 如果失败，提供安装脚本
- check.bat 自动检测并提示

**优点**：
- 兼顾两种方案的优点
- 最大灵活性

**缺点**：
- 打包脚本复杂
- 需要更多测试

## 技术细节

### robocopy 参数说明

```batch
robocopy source dest /E /NFL /NDL /NJH /NJS /nc /ns /np
```

- `/E`：复制所有子目录（包括空目录）
- `/NFL`：不列出文件名
- `/NDL`：不列出目录名
- `/NJH`：不显示作业标题
- `/NJS`：不显示作业摘要
- `/nc`：不显示文件类
- `/ns`：不显示文件大小
- `/np`：不显示进度百分比

### robocopy 退出码

- 0：没有文件被复制
- 1：文件被成功复制
- 2：存在额外的文件或目录
- 4：存在不匹配的文件或目录
- 8：复制失败
- 16：严重错误

退出码 0-7 表示成功，8+ 表示错误。
